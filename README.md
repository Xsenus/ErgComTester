# Microlux ERG-Connect

Репозиторий содержит два приложения:

- **ErgComTester** — исходная консольная утилита для диагностики подключения прибора и выгрузки данных. Проект сохранён без изменений и может использоваться для ручных проверок.
- **MicroluxErgConnect.Desktop** — WinForms‑клиент, который расширяет функциональность консольного инструмента за счёт фоновых служб, автоматических отчётов и обновлений.

## Основные возможности настольного клиента
- 🔄 **Автоматический поиск оборудования.** Приложение сканирует все доступные COM-порты параллельно, приоритетно проверяя запомненный порт прибора. При потере связи выполняется переподключение.
- 📝 **Получение данных пациентов.** После обнаружения прибора выполняется обмен по протоколу (команды 0xE0, 0xE5, 0xEA и синхронизация времени). Для каждого пациента сохраняется «сырое» бинарное представление и формируется PDF-отчет на базе QuestPDF.
- 🕒 **Фоновый режим.** Сервисы сканирования портов и синхронизации данных работают в отдельных потоках и продолжают выполнение после сворачивания окна.
- 🪟 **Системный трей.** Главное окно WinForms может быть скрыто. Управление осуществляется через контекстное меню иконки (открыть/выйти).
- ⬆️ **Автообновления.** Клиент периодически загружает JSON-манифест обновлений, при необходимости скачивает инсталлятор и позволяет запустить установку прямо из интерфейса.
- ⚙️ **Гибкие настройки.** В UI доступны интервалы сканирования портов, синхронизации пациентов и проверки обновлений, а также адрес манифеста и открытие директорий отчетов/логов.
- 📜 **Расширенное журналирование.** Все действия подробно протоколируются в файл и отображаются в окне «Журнал». Лог содержит информацию о настройках, сканировании портов, обмене данными и обновлениях.

## Системные требования
- Windows 10/11 (x86 или x64).
- .NET 8 Desktop Runtime (x86/x64).
- Стандартный драйвер виртуального COM-порта FTDI (CDC/ACM), дополнительных драйверов не требуется.

## Сборка и запуск

### Консольный тестер
> По умолчанию все проекты компилируются под архитектуру `x86`, поэтому одна и та же сборка подходит как для 32-битной, так и для 64-битной Windows. При необходимости можно переопределить целевую платформу параметром `-p:PlatformTarget=x64`.

```bash
cd ConsoleApp
dotnet build -c Release
dotnet run -c Release -- --list
```
Логи помещаются в каталог `logs` рядом с исполняемым файлом, а выгруженные данные — в `out`.

- После успешного обмена в каталоге `out/raw` сохраняются бинарные блоки (`patient_XXX.bin`),
  в `out/structured` — разобранные JSON-файлы, а в `out/pdf` — автоматически сформированные отчёты.
- Для офлайн-анализа отдельного дампа можно использовать режим `--parse`:
  ```bash
  dotnet run -c Release -- --parse=/path/to/patient_001.bin --json-out=patient_001.json --pdf-out=patient_001.pdf --clinic="Название клиники"
  ```
  Команда распарсит блок, выведет краткую сводку в лог, сохранит JSON и (опционально) PDF-отчёт.

### Настольный клиент
```bash
cd DesktopClient
dotnet build -c Release
dotnet run -c Release
```
После сборки исполняемый файл находится в `DesktopClient/bin/<Конфигурация>/net8.0-windows/`. Запуск производится через `MicroluxErgConnect.Desktop.exe`.

### Публикация для 32-битной Windows
Для поставки версии с встроенным 32-битным рантаймом можно выполнить самодостаточную публикацию:

```bash
dotnet publish DesktopClient/MicroluxErgConnect.Desktop.csproj -c Release -r win-x86 --self-contained true
```

Готовые файлы будут находиться в каталоге `DesktopClient/bin/Release/net8.0-windows/win-x86/publish/`. Для выпуска 64-битного варианта укажите идентификатор и платформу явно:

```bash
dotnet publish DesktopClient/MicroluxErgConnect.Desktop.csproj -c Release -r win-x64 -p:PlatformTarget=x64 --self-contained true
```

> ⚙️ Стандартный pipeline GitHub Actions (`dotnet build` + `dotnet publish` без явного указания RID) тоже выпускает x86-артефакт, потому что в `.csproj` по умолчанию прописаны `PlatformTarget=x86` и `RuntimeIdentifier=win-x86`. На 32-битных машинах достаточно установить [Desktop Runtime .NET 8 (x86)](https://dotnet.microsoft.com/ru-ru/download/dotnet/8.0), распаковать архив из CI и запустить `MicroluxErgConnect.Desktop.exe`.

## Обновления
- URL манифеста и частоту проверки можно задать на вкладке «Обновления».
- Манифест ожидается в формате JSON:
  ```json
  {
    "version": "1.2.3",
    "downloadUrl": "https://example.com/MicroluxErgConnect_1.2.3.exe",
    "releaseNotes": "Описание изменений",
    "releasedAt": "2025-09-07T12:00:00Z"
  }
  ```
- При включённой автозагрузке обновление скачивается в `%AppData%/MicroluxErgConnect/updates/` и готово к установке.

## Каталоги приложения
- Настройки: `%AppData%/MicroluxErgConnect/settings.json`
- Логи: `Документы/Microlux ERG Connect/Logs/`
- Отчёты: `Документы/Microlux ERG Connect/Reports/<дата>/`

## Telegram-уведомления
Клиент умеет отправлять подробные уведомления в Telegram о запуске и остановке приложения, подключении прибора,
ходе синхронизации, сформированных отчётах и ручных конвертациях файлов. Обычные строки журнала при этом не
пересылаются, чтобы не заспамить чат. Параметры задаются в `settings.json` после первого запуска программы.

1. Завершите работу приложения (Telegram-настройки перечитываются только при сохранении настроек из клиента).
2. Откройте файл `%AppData%/MicroluxErgConnect/settings.json` в любом текстовом редакторе и добавьте/измените блок
   `"telegram"`.
3. Укажите токен бота и идентификатор чата (числовой `chatId` из Telegram). Пример:

   ```json
   {
     "telegram": {
       "enabled": true,
       "botToken": "8258402461:AAF3-llnHwTfr0HiBiRTgjJBq8c9SOY2r90",
       "chatId": "314241927",
       "forwardReports": true,
       "forwardJson": true,
       "forwardRawData": true,
       "sendLogOnExit": true
     }
   }
   ```

   Остальные параметры управляют пересылкой PDF/JSON/RAW файлов и финального лога при закрытии.
4. Сохраните файл и запустите программу заново. При старте в журнале появится строка `Telegram: enabled=да, ...` с
   резюме настроек. Если бот включён, но токен или chatId не заданы, в лог попадёт предупреждение.

> ⚠️ Токен хранится в открытом виде. Убедитесь, что к файлу настроек нет постороннего доступа.

## Настройка протокола связи
Приложение использует параметры COM-порта 115200, 8-N-1 без аппаратного контроля потока. После получения каждого блока данных отправляется подтверждение `0xE3`, что предотвращает переполнение буфера FTDI. По завершении выгрузки производится синхронизация времени командой `DTdd-mm-yyyy hh:mm<kc>`.

## Структура решения
- `ConsoleApp/` — исходники консольного тестера (`ErgComTester.csproj`).
- `DesktopClient/` — настольное приложение (`MicroluxErgConnect.Desktop.csproj`).
  - `Program.cs` — WinForms-точка входа и настройка окружения.
  - `Infrastructure/` — сервис-локатор, команды и вспомогательные классы.
  - `Models/` — модели данных (настройки, журналы, обновления, информация о приборе).
  - `Services/` — фоновые службы: мониторинг портов, генерация отчётов, автоматические обновления, журнал.
  - `ViewModels/` — логика представления главного окна.
  - `Views/` — формы WinForms (`MainForm` и вспомогательные контролы).

## Отладка обмена
- В журнале доступны дампы команд и ответов (HEX) для каждого COM-порта.
- При необходимости можно очистить запомненный порт кнопкой «Очистить запомненный порт», чтобы принудительно выполнить полное сканирование.
- Сырые бинарные файлы пациентов сохраняются рядом с PDF-отчётами для дополнительного анализа.
