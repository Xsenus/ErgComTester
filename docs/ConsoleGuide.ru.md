# Руководство по работе с консольной утилитой ErgComTester

Документ описывает полный цикл взаимодействия с прибором МЛ-210 VET «Микролюкс» через консольную утилиту `ErgComTester`, а также поясняет внутреннюю логику, журналирование и правила обработки данных.

## 1. Назначение утилиты
- Поиск подключённого прибора по всем доступным COM-портам.
- Проверка связи и чтение структуры `COMMON_INFO`.
- Последовательная выгрузка всех пациентов из памяти прибора.
- Контроль целостности и повторная загрузка при ошибках.
- Создание отчётного пакета (`logs/`, `out/`, ZIP-архив) для передачи в техническую поддержку.

## 2. Подготовка и запуск
1. Убедитесь, что драйвер виртуального COM-порта установлен и прибор отображается в системе.
2. Соберите приложение (или используйте уже собранный `ErgComTester.exe`).
3. Запустите командой:
   ```bash
   ErgComTester.exe --auto
   ```
   Дополнительные ключи: `--list` (только перечисление портов), `--single --port=COMx` (проверка конкретного порта), `--nofetch` (без выгрузки пациентов), `--nozip` (без архива поддержки), `--rtctime` (синхронизация часов), `--nodtr/--norts/--notoggle` (управление линиями).

## 3. Автоматический сценарий `RunAuto`
1. **Журнал запуска.** В лог выводится версия приложения, параметры командной строки и список портов.
2. **Сканирование портов.** Для каждого найденного порта выполняется `TestSinglePort`:
   - открывается `SerialPort` (115200 8N1);
   - по запросу выполняется сброс линий DTR/RTS;
   - отправляется `PING (0xE0)` и ожидается ответ `COMMON_INFO`.
3. **Анализ `COMMON_INFO`.** После получения валидного блока записываются:
   - `Report_Name` — название отчёта;
   - `Device_Name` — модель прибора;
   - `Software_Rev` — версия прошивки;
   - `Total_Num_ID` — количество пациентов.
4. **Выгрузка пациентов.** Если не указан `--nofetch`, выполняется цикл по количеству пациентов (минимум один запрос):
   - отправка `GET (0xE5)`;
   - чтение «сырых» данных пациента;
   - HEX-дамп и сохранение блока в `out/raw/patient_XXX.bin`;
   - проверка контрольной суммы (`ID_KS`);
   - разбор структуры пациента (ID, тип животного, дата/время теста, количество тестов, текст заключения).
   При ошибке контроля отправляется `REPEAT (0xEA)` и сохраняется повторный блок.
5. **Синхронизация времени.** С ключом `--rtctime` формируется команда `DTdd-mm-yyyy hh:mm<kc>` с контрольной суммой, отправляется прибору и фиксируется ответ.
6. **Завершение.** Создаётся текстовый `summary_*.txt` и, при необходимости, ZIP-архив `ERG_Support_*.zip`, содержащие логи и выгруженные данные.

## 4. Журналирование и контроль целостности
- Класс `Logger` пишет каждое действие с точным временем и цветовой индикацией уровней (`INFO`, `WARN`, `ERROR`, `DEBUG`).
- Команды и ответы выводятся в HEX (метод `HexDump`) с указанием длины, смещения и ASCII-представления.
- Все действия фиксируются одновременно в консоль и файл `logs/ergtester_<timestamp>.log`, что обеспечивает трассировку.
- Каждая операция чтения/записи обёрнута в обработчики ошибок: исключения логируются и приводят к повторным попыткам.
- Сырые блоки сохраняются до разбора, поэтому даже при сбое парсинга данные остаются целыми.

## 5. Форматы данных
Описание структур находится в [`docs/ProtocolGuide.ru.md`](ProtocolGuide.ru.md). Ключевые моменты:
- `COMMON_INFO` содержит ASCII-строки длиной 64/64/6 байт с завершающим `0x00`, счётчик пациентов и контрольную сумму.
- Блок пациента включает поля `Patient_ID` (big-endian), `Animal_Type`, строку даты/времени (18 байт), счётчик тестов, массив структур `TEST_DATA`, описание заключения в Windows-1251 и контрольную сумму.
- Контрольная сумма — младший байт суммы всех предыдущих байт структуры. Повторные запросы `0xEA` обеспечивают получение корректной копии.

## 6. Безопасность данных
- Перед обработкой каждый блок пишется на диск, что предотвращает потерю данных при сбое приложения или питания.
- Проверка контрольных сумм позволяет обнаружить повреждения. При несоответствии автоматически выполняется `REPEAT (0xEA)`.
- Архив поддержки создаётся в конце работы; если опция `--nozip` отключена, готовый пакет можно передать инженерам без изменения оригинальных файлов.
- В режиме `--single` можно вручную проверить любой COM-порт, не затрагивая остальные устройства системы.

## 7. Использование с подключённым прибором
1. Подключите прибор и дождитесь его появления в системе (COM-порт).
2. Запустите `ErgComTester.exe` без аргументов или с нужными ключами.
3. Наблюдайте лог в консоли: при обнаружении прибора появится блок «Device detected…» с данными.
4. После завершения проверьте каталоги `logs/` и `out/`. Файл `summary_*.txt` содержит общую информацию о сеансе.
5. Для передачи отчёта используйте созданный архив `ERG_Support_*.zip` (если не отключали упаковку).

## 8. Частые вопросы
- **Можно ли подключить несколько приборов?** Утилита перебирает все COM-порты и остановится на первом приборе, успешно ответившем на пинг.
- **Что делать при отсутствии ответа?** Проверьте параметры порта, кабель и доступность устройства. Лог покажет ошибку «No reply» или исключение открытия.
- **Как изменить количество попыток?** Используйте ключ `--retries=<n>`. Между попытками выдерживается задержка `150 мс`.
- **Где найти исходные бинарные данные?** В каталоге `out/raw/`, файл `patient_XXX.bin` соответствует каждой передаче.
