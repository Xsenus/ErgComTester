# Алгоритм чтения данных с порта

Документ описывает подход, применённый в консольном тестере и настольном клиенте для чтения ответов от прибора по последовательному интерфейсу.

## Ключевые цели

* Повысить устойчивость к различным прошивкам и драйверам, реагирующим на чтение по-разному.
* Предоставить несколько независимых способов чтения одного и того же пакета.
* Запоминать наиболее надёжный способ для каждого порта в рамках текущего запуска, чтобы избежать лишних повторов.

## Набор стратегий

В `ErgIo.ReadChunk` определены три стратегии:

1. **Polling** — существующая реализация: периодически проверяет `BytesToRead`, считывает доступный объём и ждёт `quietMs`, если данных нет.
2. **BlockingChunk** — опирается на блокирующие вызовы `SerialPort.Read` с буфером в 1024 байта и тайм-аутом, равным `quietMs` (не меньше 50 мс). Позволяет получать данные даже при отсутствии корректного значения `BytesToRead`.
3. **BlockingByte** — считывает поток побайтно (размер пакета не важен) и хорошо подходит для драйверов, которые не отдают большие блоки за один вызов.

Каждая стратегия работает в том же временном окне `maxWindowMs` и возвращает накопленные байты.

## Выбор и запоминание стратегии

* Для каждого имени порта (`SerialPort.PortName`) ведётся карта «порт → стратегия».
* При чтении список стратегий формируется так: сначала сохранённая для порта стратегия, затем остальные.
* После успешного чтения (объём >= `minExpectedSize`, а если он равен 0 — достаточно получить хоть что-то) стратегия сохраняется и в следующий раз используется первой.
* Если ни один способ не дал данных, возвращается лучший (самый длинный) ответ, а в лог пишется отладочное сообщение.

Таким образом, при первом запуске последовательно перебираются все способы, а при повторных обращениях затраты сводятся к минимуму.

## Журналирование

* При выборе новой стратегии в лог пишется строка уровня DEBUG с указанием порта и названия стратегии.
* В настольном клиенте дополнительная отладочная запись фиксирует длительность приёма и размер ответа.

## Где используется

* `ConsoleApp/ErgIo.cs` — консольный тестер, который обращается к `ReadChunk` напрямую.
* `DesktopClient/ErgIo.cs` — настольное приложение использует ту же реализацию и разделяет таблицу предпочтений.
* `DesktopClient/Services/DeviceMonitorService.cs` — обёртка для логирования длительности вызова использует `ErgIo.ReadChunk`.

## Тестирование

Сборка проектов через `dotnet build` проверяет корректность компиляции.
