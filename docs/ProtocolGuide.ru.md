# Microlux ERG-Connect — руководство по работе с прибором МЛ-210 VET «Микролюкс»

## Назначение
Microlux ERG-Connect — настольное WinForms-приложение для взаимодействия с прибором МЛ-210 VET «Микролюкс» через виртуальный COM-порт. Программа автоматизирует поиск устройства, обмен данными, формирование PDF-отчётов и синхронизацию времени, сопровождая каждое действие подробным журналированием.

## Подготовка оборудования
1. Установите стандартный драйвер виртуального COM-порта FTDI (CDC/ACM). Дополнительных драйверов не требуется.
2. Подключите прибор к компьютеру USB-кабелем. Убедитесь, что устройство появилось в «Диспетчере устройств» в разделе «Порты (COM и LPT)».
3. Запустите Microlux ERG-Connect. При первом запуске приложение автоматически создаст рабочие каталоги:
   - `%AppData%/MicroluxErgConnect/settings.json` — настройки.
   - `Документы/Microlux ERG Connect/Logs/` — журналы.
   - `Документы/Microlux ERG Connect/Reports/<дата>/` — PDF-отчёты и бинарные дампы пациентов.
4. При необходимости отредактируйте интервалы опроса, каталог отчётов и другие параметры на вкладке «Настройки».

## Общий рабочий цикл приложения
1. **Поиск приборов.** Сервис сканирования просматривает все COM-порты (115200, 8, N, 1) и отправляет команду `0xE0` (пинг). Прибор, подключённый к проверяемому порту, отвечает структурой `COMMON_INFO`.
2. **Инициализация сеанса.** После успешного ответа фиксируется номер порта, в журнал заносится модель, версия прошивки и количество пациентов в памяти прибора.
3. **Загрузка данных пациентов.** Для каждого пациента последовательно отправляется команда `0xE5`. Прибор возвращает структурированный блок, содержащий все тесты пациента (`TEST_DATA`), текст заключения и контрольную сумму.
4. **Контроль целостности.** Приложение сверяет контрольную сумму (`ID_KS`). При расхождении отправляется команда `0xEA` для повторной передачи текущего пациента.
5. **Формирование отчёта.** Для каждой записи создаётся PDF-файл по шаблону, учитывающему требования к полям, размерам графиков и размещению тестов. Одновременно сохраняется «сырой» бинарный дамп ответа прибора.
6. **Синхронизация времени.** После обработки всех пациентов отправляется команда `DTdd-mm-yyyy hh:mm<kc>`, где `<kc>` — младший байт суммы всех предыдущих байт команды. Прибор обновляет встроенные часы.
7. **Завершение.** Клиент воспроизводит звуковой сигнал, уведомляющий пользователя о готовности отчётов, и оставляет запись в журнале.

## Управление интерфейсом
- Главное окно можно закрыть крестиком — по умолчанию оно минимизируется в системный трей. Контекстное меню значка содержит команды «Открыть» и «Выход».
- Журнал событий отображается в таблице и сохраняется в файл. При необходимости можно включить фильтры и экспорт.
- Вкладка «Настройки» позволяет менять интервалы опроса, путь к отчётам и URL манифеста обновлений. Значения проверяются и автоматически приводятся к допустимым диапазонам.
- На вкладке «Обновления» отображается состояние проверки новой версии и доступна ручная установка скачанного обновления.

## Протокол обмена командами
| Команда | Назначение | Ответ прибора |
| ------- | ---------- | -------------- |
| `0xE0`  | Пинг-проверка COM-порта и получение общей информации. | Структура `COMMON_INFO` со служебными сведениями и контрольной суммой. |
| `0xE5`  | Передача данных очередного пациента. | Структурированный блок: идентификатор пациента, сведения о тестах (`TEST_DATA`), текст заключения, контрольная сумма. |
| `0xEA`  | Повтор текущих данных пациента после ошибки контроля. | Полный повтор предыдущего блока пациента без перехода к следующему. |
| `DTdd-mm-yyyy hh:mm<kc>` | Установка текущей даты и времени после завершения обмена. | Прибор принимает значение и подтверждает установку внутренним сигналом (подтверждение фиксируется косвенно по журналу). |

**Параметры COM-порта:** скорость 115200 бод, 8 бит данных, без чётности, 1 стоп-бит, аппаратный контроль потока отсутствует.

## Структура `COMMON_INFO`
```
typedef struct
{
    unsigned char    Report_Name[64];  // Название отчета (строка с завершающим 0)
    unsigned char    Device_Name[64];  // Название прибора (строка с завершающим 0)
    unsigned char    Software_Rev[6];  // Версия ПО прибора (строка с завершающим 0)
    unsigned char    Total_Num_ID;     // Количество пациентов в памяти прибора
    unsigned char    KS;               // Контрольная сумма (младший байт суммы всех предыдущих полей)
} COMMON_INFO;
```

## Структура данных пациента
Блок, передаваемый в ответ на `0xE5`, содержит:
- `Patient_ID` — уникальный 32-битный идентификатор (старший байт первым).
- `Animal_Type` — вид животного: 0 — кошка, 1 — собака, 2 — кролик, 3 — лошадь, 4 — прочие.
- `Test_Date_Time[18]` — строка даты и времени исследования, завершается нулевым байтом (пример: `25/09/2025  19:26`).
- `Total_Num_Tests` — количество проведённых тестов.
- `TEST_DATA` — массив структур тестов (см. ниже).
- `Description[500]` — текст заключения в кодировке Windows-1251, завершается нулём.
- `ID_KS` — контрольная сумма младшего байта алгебраической суммы всех байт начиная с `Patient_ID`.

Особенности интерпретации:
- Цвета графиков (`Graph_RGB`) задаются в формате RGB, например красный — `(255, 0, 0)`.
- Флаг `a_wave_exist` определяет, нужно ли отображать подписи «a-волна» и «b-волна».
- Значения 255/65535 в полях амплитуд и маркеров означают отсутствие данных и выводятся как «— —».
- Поля `OD_is_Flat`/`OS_is_Flat` заменяют числовые значения на надпись `FLAT`.

## Формирование PDF-отчётов
При генерации отчётов соблюдаются следующие требования:
- Высота поля графиков — 45–50 мм, включая подписи осей.
- Ось X подписывается «мс», ось Y — «мкВ».
- На одной странице размещается не более двух тестов. Между тестами — минимум 15–20 мм свободного пространства.
- Если тест почти помещается (не хватает 5–10 мм), допускается уменьшение интервала между тестами до 10 мм и сокращение нижнего поля до 15 мм.
- Поля страницы: слева ≥ 20 мм, справа ≥ 15 мм, сверху ≥ 20 мм, снизу ≥ 20 мм (в крайнем случае — 15 мм).
- Заключение (до 500 символов) печатается шрифтом 12 пт. Если отчёт состоит из одного теста и заключение не помещается, шрифт допускается уменьшить до 10 пт; если текст всё равно не входит, весь блок переносится на следующую страницу.
- При многополосных отчётах страницы нумеруются в нижней части.
- Примеры верстки приведены в приложенных макетах (см. изображения в ТЗ).

## Контроль ошибок и повторная передача
- Каждая структура заканчивается контрольной суммой — младшим байтом алгебраической суммы всех предшествующих байт.
- При несоответствии контрольной суммы журнал фиксирует ошибку, данные помечаются как недействительные, и выполняется команда `0xEA` для повторной отправки.
- После трёх безуспешных попыток повторения пользователь получает уведомление и рекомендацию проверить соединение.

## Журналирование и диагностические инструменты
- Все команды и ответы фиксируются в журнале с пометкой времени и номера порта. При необходимости лог выводит HEX-дампы полезной нагрузки.
- Системные сообщения (ошибки, предупреждения, информационные события) сохраняются в ежедневные файлы, доступные через интерфейс.
- В случае необработанных исключений применяется глобальный обработчик, записывающий стек вызовов и параметры окружения.

## Настройки и обновления
- Интервалы опроса и пути каталогов вводятся вручную; приложение проверяет корректность (минимальные и максимальные значения, корректный URL). Неверные значения автоматически корректируются и сопровождаются предупреждением в журнале.
- Проверка обновлений выполняется по URL манифеста. Файл ожидается в формате JSON (`version`, `downloadUrl`, `releaseNotes`, `releasedAt`).
- Загрузка инсталлятора происходит в `%AppData%/MicroluxErgConnect/updates/`. После скачивания пользователь может запустить установку из интерфейса.

## Устранение неполадок
1. **Прибор не найден.** Убедитесь, что COM-порт отображается в системе и не занят другим приложением. Используйте кнопку «Очистить запомненный порт» для повторного полного сканирования.
2. **Ошибки контрольной суммы.** Проверьте качество USB-кабеля и стабильность питания. При повторяющихся ошибках выполните повторное сканирование.
3. **Отчёты не создаются.** Проверьте права записи в каталог отчётов и свободное место на диске. Сообщения об ошибке доступны в журнале.
4. **Нет звукового сигнала.** Убедитесь, что звук включён в системе Windows и приложение не запущено в режиме «Без звука».
